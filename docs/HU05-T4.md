# HU05-T4: botón «Dar de baja»

Tarea: [SCRUM-52](https://itla-fitlab-grupo2.atlassian.net/browse/SCRUM-52). Rama: `feature/HU05-T4-boton-baja`, creada desde `develop`.

## Alcance

Componente JavaScript independiente, basado en el prototipo HTML de Ángel. Se conecta a un botón existente; conserva su contenido, iconos y clases, sin definir estilos o una ventana de confirmación. No necesita un framework ni instala dependencias.

La versión revisada de `develop` contiene una API .NET 9, sin pantalla de miembros, autenticación ni endpoint de baja. El componente queda preparado dentro del repositorio; la conexión con la pantalla y los servicios reales está pendiente. No se ha activado un sitio estático en la API.

- Ángel / T4: visibilidad, acción del botón, bloqueo temporal y eventos para actualizar la interfaz.
- T5 y diseño de Geisi: pantalla y confirmación visual.
- Backend de Jeison: autorización real, baja lógica, persistencia y respuesta del servidor.

## Conexión con la pantalla definitiva

El HTML inicial debe ocultar y deshabilitar el botón para evitar que aparezca antes de cargar los permisos:

```html
<button id="dar-de-baja" type="button" hidden disabled>Dar de baja</button>
```

Desde el módulo de la pantalla:

```js
import { conectarBotonBaja } from "./frontend/hu05/boton-baja.js";

const boton = document.querySelector("#dar-de-baja");
const conexion = conectarBotonBaja(boton, {
    miembroId: miembro.id,
    activo: miembro.activo,
    autorizado: false
});

// Cuando la pantalla disponga de la sesión y los adaptadores definitivos:
conexion.actualizar({
    autorizado: permisosServidor.puedeDarDeBaja === true,
    confirmarBaja: id => confirmacionT5.solicitar(id),
    solicitarBaja: id => adaptadorJeison.darDeBaja(id)
});

// Al retirar la pantalla o cambiar de miembro:
// conexion.destruir();
```

Los nombres `miembro`, `permisosServidor`, `confirmacionT5` y `adaptadorJeison` representan datos y servicios que aún debe proporcionar la pantalla oficial. No son APIs existentes. La ruta de importación se ajustará a esa pantalla. No se inventa un rol ni una URL del backend.

### Contratos de los adaptadores

`confirmarBaja(miembroId)` devuelve `true` o una promesa que resuelva exactamente a `true` únicamente cuando T5 confirme. Una cancelación o cualquier otro valor impide llamar al backend.

`solicitarBaja(miembroId)` realiza la petición real, comprueba la respuesta HTTP y traduce el resultado verificado al contrato del componente:

```js
// Éxito: solo después de que el servidor confirme la baja persistida.
{ exito: true, estado: "inactivo" }

// Rechazo del servidor:
{ exito: false, mensaje: "No se pudo realizar la baja." }
```

Este es un contrato de adaptación de la interfaz, tomado del prototipo; el formato real de Jeison está pendiente de acordar. Una respuesta HTTP `Response` sin transformar, una respuesta ambigua o una excepción no anuncian éxito. El componente no envía un empleado ni un permiso elegido por el cliente: el backend debe identificar y autorizar al empleado en cada solicitud.

El permiso es explícito: solo el booleano `true` muestra el botón. Sin permiso queda oculto y sin acción; si el estado del miembro es desconocido o inactivo, o falta un adaptador, queda deshabilitado. El ID queda fijo durante la vida de la conexión para evitar que una respuesta termine aplicándose a otro miembro seleccionado.

`actualizar()` permite modificar `autorizado`, `activo`, `confirmarBaja` y `solicitarBaja`. Un cambio durante la confirmación invalida esa confirmación. `destruir()` retira el manejador, oculta el botón e ignora respuestas tardías. Una solicitud ya enviada no se deshace al retirar el botón ni al cambiar los permisos; el servidor sigue siendo responsable de la operación y de impedir aplicaciones duplicadas.

### Eventos de interfaz

El botón emite `hu05:baja-estado`, propagado a su contenedor, con:

```js
{ miembroId, tipo, mensaje }
```

`tipo` puede ser `confirmando`, `procesando`, `cancelado`, `error` o `exito`. Geisi puede mostrar el mensaje donde corresponda, usando `textContent` y una región `role="status"`. El componente conserva el texto del botón y expone el procesamiento mediante `disabled` y `aria-busy`.

Solo ante `exito` debe la pantalla actualizar el estado visual a inactivo. Cancelar o fallar conserva el estado anterior y permite reintentar. Los mensajes no se deben insertar como HTML.

## Pruebas en navegador real

Desde la raíz de esta rama:

```bash
python3 -m http.server 8768 --bind 127.0.0.1
```

Abrir `http://127.0.0.1:8768/tests/hu05-t4/`. La página ejecuta las pruebas automáticamente y presenta los resultados. Utiliza adaptadores simulados solo dentro de la suite; no envía bajas reales ni necesita SQL Server. Recargar la página repite la ejecución.

La muestra `http://127.0.0.1:8768/tests/hu05-t4/demo.html` permite revisar manualmente la visibilidad, la cancelación, el éxito y el error. Sus controles de permisos y resultados son exclusivos de pruebas y no forman parte del componente de producción.

Casos cubiertos: permiso ausente o inválido, autorización explícita, estado inactivo o desconocido, conexión posterior de T5 y del backend, cancelación, respuestas ambiguas, éxito, fallos, reintentos, doble pulsación, revocación de permisos, confirmaciones obsoletas, retirada del componente y configuración inválida.

Verificación de la API:

```bash
dotnet build TuProyecto.csproj --configuration Release
```

`TuProyecto.csproj` excluye `tests/**` de contenido y archivos auxiliares para que la suite no forme parte de la publicación. No hay cambios en controladores, modelos, base de datos ni `Program.cs`.
